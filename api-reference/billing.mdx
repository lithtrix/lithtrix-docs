Pricing shape ruled D173 (2026-08-19) — retires the Spark/Sprint/Mission/Deploy pack model in favor of rolling-30-day free floors plus per-action credit pricing. **The endpoints below still reflect the pre-D173 pack shape in code** — a slider checkout endpoint is not yet built (Stripe stays gated on D125 regardless). Treat `GET /v1/capabilities` as authoritative for what's actually callable today.

## Check status

```bash
GET /v1/billing
Authorization: Bearer ltx_your_key
```

Returns a snapshot of the authenticated agent:

| Field | Meaning |
|-------|---------|
| `tier` | Currently `spark`, `sprint`, `mission`, or `deploy` in code (pack-era values — pending update to the D173 shape) |
| `credits_remaining_usd` | Current spendable credit balance (USD string, 4 decimal places) |
| `credits_expire_at` | ISO-8601 UTC — when the current pack expires (`null` if no active pack; not applicable once slider top-up ships, since D173 sets no fixed expiry) |
| `tier_label` | Human-readable tier name |
| `auto_topup` | `true` if auto top-up is configured |
| `over_limit` | `true` if storage, memory, or parse quota is at cap |
| `memory_ops_this_month` | Memory operations logged this UTC month |
| `memory_storage_bytes` | KV JSON storage (bytes) |
| `blob_embed_storage_bytes` | Bytes used by parsed document chunk embeddings |
| `combined_memory_storage_bytes` | `memory_storage_bytes + blob_embed_storage_bytes` |
| `search_calls_this_month` | Web-discovery calls this UTC month |
| `browse_calls_this_month` | Browse calls this UTC month — metered per call, no pack required (D173) |
| `parse_ops_this_month` / `parse_ops_lifetime` | Parse usage |

## Free floors (D173)

Before any credit is charged:

| Action | Free floor | Window |
|---|---|---|
| Memory write | 1,000 | Rolling 30 days |
| Search | 50 | Rolling 30 days |
| Browse | None | Metered from the first call |

Past the floor: memory write **1 credit ($0.01)**, search **2 credits ($0.02)**, browse **3–5 credits ($0.03–$0.05)**. See [Pricing](/pricing) for the full breakdown and the volume-discount slider rates.

## Buy credits

```bash
POST /v1/billing/packs/checkout
Authorization: Bearer ltx_your_key
Content-Type: application/json

{
  "pack": "sprint"
}
```

**This endpoint still takes the pre-D173 `pack` enum** (`sprint` / `mission` / `deploy`) — a slider endpoint that accepts an arbitrary credit amount at the D173 volume-discount rate is not yet built. Nobody has ever completed a purchase through this endpoint (`stripe_webhook_events` is empty), so there is no in-flight migration to manage; it's an open engineering ticket, not a breaking change for existing users.

Once the slider endpoint ships, `pack` will be replaced by a `credits` integer, priced per the D173 table:

| Credits | Rate | Discount |
|---|---|---|
| 1–999 | $0.01/credit | base |
| 1,000–4,999 | $0.009/credit | 10% |
| 5,000–19,999 | $0.0075/credit | 25% |
| 20,000+ | $0.006/credit | 40% |

## Auto top-up

Set a threshold and saved payment method — Lithtrix refills automatically when your balance drops below it.

```bash
POST /v1/billing/auto-topup
Authorization: Bearer ltx_your_key
Content-Type: application/json

{
  "enabled": true,
  "threshold_usd": "5.00",
  "pack": "sprint",
  "payment_method_id": "pm_..."
}
```

The `pack` field here is subject to the same pending endpoint update as checkout above.

## Webhook

`POST /v1/billing/webhook` — Stripe-signed events. Configure `STRIPE_WEBHOOK_SECRET` on the host.

## Environment (ops)

- `STRIPE_PRICE_PACK_SPRINT` — Stripe Price ID for Sprint (pack-era; pending D173 slider migration)
- `STRIPE_PRICE_PACK_MISSION` — Stripe Price ID for Mission (pack-era; pending D173 slider migration)
- `STRIPE_PRICE_PACK_DEPLOY` — Stripe Price ID for Deploy (pack-era; pending D173 slider migration)
- `STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET`

See also [`GET /v1/capabilities`](https://api.lithtrix.ai/v1/capabilities) for the `pricing` block and per-call rates, and [Pricing](/pricing) for the full D173 shape.
